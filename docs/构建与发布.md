# 构建与发布

## 1. 环境要求

| 组件 | 版本 | 备注 |
|---|---|---|
| Node.js | 见 `.nvmrc` | 只用来装依赖和打包 JS |
| JDK | **17**（构建）+ 21 可选 | Gradle 工具链**必须能找到 JDK 17**，否则会去 GitHub 下载工具链，网络差会假死 |
| Android SDK | platform 36 / build-tools 36 | `ANDROID_HOME` 指向它 |
| NDK | 26.1 | native 依赖编译需要 |
| Gradle | 8.8（wrapper 自动） | 首次会下载发行包 |

Gradle 若找不到 JDK 17，在 `~/.gradle/gradle.properties` 写：

```properties
org.gradle.java.installations.paths=/path/to/jdk17,/path/to/jdk21
```

国内网络建议配镜像（否则 `plugins.gradle.org` 极慢）：

```groovy
// ~/.gradle/init.gradle
allprojects {
    repositories {
        maven { url 'https://maven.aliyun.com/repository/google' }
        maven { url 'https://maven.aliyun.com/repository/public' }
        maven { url 'https://maven.aliyun.com/repository/gradle-plugin' }
    }
}
```

## 2. 构建

```bash
npm install

# 方式一：直接用 gradle
cd android && ./gradlew assembleRelease        # Windows: gradlew.bat

# 方式二：用仓库脚本（自动探测 JDK / SDK 环境变量）
../tools/build.sh                              # Windows: ..\tools\build.bat
```

产物目录：`android/app/build/outputs/apk/release/`

| 文件 | 用途 |
|---|---|
| `mx-music-v1.0-arm64-v8a.apk` | **手机安装用这个**（绝大多数设备） |
| `mx-music-v1.0-armeabi-v7a.apk` | 老 32 位设备 |
| `mx-music-v1.0-universal.apk` | 全架构，体积约大一倍 |

增量构建约 1 分钟，首次 5 分钟左右。

## 3. 签名

仓库**不含任何签名文件**（`.gitignore` 已排除 `keystore.properties`、`*.keystore`、`*.jks`）。

```bash
# 生成自己的 keystore
keytool -genkeypair -v -storetype PKCS12 -keystore my-release.keystore \
  -alias mykey -keyalg RSA -keysize 2048 -validity 10000

# 配置
cp android/keystore.properties.example android/keystore.properties
# 然后填入 storeFile / storePassword / keyAlias / keyPassword
```

**不配置也能构建**：`android/app/build.gradle` 会检测文件是否存在，
没有则自动退回 debug 签名（仅适合自己安装测试，不能用于分发）。

## 4. 三个「版本号」

| 名称 | 位置 | 谁维护 | 作用 |
|---|---|---|---|
| `versionName` | `package.json` → `"version"` | 手动，固定 1.0 | 显示用 |
| `versionCode` | `package.json` → `"versionCode"` | **脚本自动 +1** | Android 判定升级，必须单调递增 |
| `MX_BUILD` | `src/config/constant.ts` | **脚本自动同步** | 关于页显示的构建号 |

APK 内的实际 `versionCode = NNN × 1000 + ABI 码`（arm64-v8a = 3），
例如构建号 b131 → `131003`。这是按 ABI 拆包的固定规则。

> ⚠️ 历史教训：`MX_BUILD` 曾是手写字符串，与 `versionCode` 脱钩，
> 导致连续三个版本关于页显示的构建号没变。现在由脚本统一维护，**不要手改**。

## 5. 发布脚本

```bash
python tools/pack_mx.py             # 正常发布（版本号 +1）
python tools/pack_mx.py --dry       # 只预览会改什么，不写不构建
python tools/pack_mx.py --no-bump   # 只重打包，不动版本号（改资源/小修时用）
```

它依次做：

1. `versionCode` +1 —— `--no-bump` 时跳过
2. 同步 `MX_BUILD = 'b<新版本号>'` —— `--no-bump` 时保持不动
3. 调构建脚本；**失败就中止，不产出**
4. 复制 `arm64-v8a` APK 到指定投放目录，命名 `MX_Music_v1.0_bNNN.apk`
5. **只删「紧邻上一版」**（出 b137 时只删 b136），更早版本和手动存档一律保留

> 早期版本这里用的是 `glob('MX_Music_v1.0_b*.apk')` 全删，会把手动保存的旧包一起删掉（`os.remove`，不进回收站）。已修正，不要改回去。

脚本顶部的路径常量需要按自己的环境改：

```python
ROOT      = r'<仓库根目录>'
BUILD_BAT = r'<tools/build.bat>'
DESK      = ...
FTP       = ...
APK       = <ROOT>/android/app/build/outputs/apk/release/mx-music-v1.0-arm64-v8a.apk
```

## 6. 验证发布物

### 6.1 看 versionCode

```bash
$ANDROID_HOME/build-tools/36.0.0/aapt dump badging MX_Music_v1.0_bNNN.apk | head -1
# package: name='cn.toside.music.mobile.mod' versionCode='NNN003' versionName='1.0'
```

### 6.2 确认代码进包了

Hermes 字节码里字符串编码不一致：**中文是 UTF-16LE，短 ASCII 是 UTF-8**。
查错编码会得到 0 命中，别误判成「没打进」。

```python
import zipfile
d = zipfile.ZipFile('MX_Music_v1.0_bNNN.apk').read('assets/index.android.bundle')
print('b131', d.count('b131'.encode('utf-8')))        # 构建号 → utf-8
print('构建', d.count('构建'.encode('utf-16-le')))     # 中文 → utf-16-le
```

### 6.3 确认图标进包了

图标 PNG 是预压缩图，aapt 不再重压，包内条目字节数应与 `res/` 一致；
只改图标时 APK 体积大约变化 39 KB。

### 6.4 装机后

「设置 → 关于」应显示 `v1.0（NNN）· 构建 bNNN`。
桌面图标有缓存：没变化就把图标移除再拖回，或重启启动器，不必重装。

## 7. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 构建卡住 / 下载不动 | 缺 JDK 17，Gradle 去 GitHub 下工具链 | 安装 JDK 17 并写入 `java.installations.paths` |
| 依赖下载极慢 | 默认走 plugins.gradle.org | 配阿里云镜像 |
| `assembleRelease` 报签名错误 | 没有 keystore.properties | 见第 3 节；不配置会自动退 debug 签名 |
| 装完版本号没变 | 装的是旧 APK | `aapt dump badging` 核对 versionCode |
| 改图标没生效 | 只跑了出图脚本，没写进 `res/` | 必须再跑 `tools/gen_mx_assets.py` |
| bash 里调 bat 报「不是内部或外部命令」 | bash 吃掉反斜杠 | 用引号：`cmd.exe /c 'D:\path\build.bat'` |

## 7. 发布凭据管理（重要）

推送代码用 **SSH 密钥**，不用 token。两者的分工：

| 用途 | 凭据 | 存放位置 | 有效期 |
|---|---|---|---|
| 推代码 / 打 tag | SSH 密钥（ed25519） | `~/.ssh/id_ed25519_github`，公钥已加入 GitHub 账号 | 长期 |
| 调 GitHub API（发 Release、改仓库信息） | PAT（Personal Access Token） | **当次命令的临时变量，用完即删** | 7 天以内 |

### 为什么 PAT 绝不能写进文档

PAT 等同于账号密码：拿到它的人可以改代码、删仓库、发任意 Release。
本项目仓库是 **public**，写进任何被 git 跟踪的文件 = **推上去的瞬间全网可见**，
而且会永久留在 git 历史里——事后删除也能从历史中翻出来。

### 需要时怎么生成（1 分钟）

1. 打开 <https://github.com/settings/tokens> → `Generate new token (classic)`
2. Note 随便填（如 `mx-music-temp`），Expiration 选 **7 days**
3. 权限只勾 **`repo`**
4. 复制后**只在当次命令里用**：

```bash
GH_TOKEN=ghp_xxx python tools/publish_release.py    # 脚本从环境变量读
```

5. 用完立刻回同一页面 **Delete**

### 绝对不要做

- 写进 `.md` / `.py` / `.json` 等任何会被提交的文件
- 写进 `git config`（会明文留在 `.git/config`）
- 贴到公开 issue、聊天群、截图里

### SSH 密钥是什么

文件名 `~/.ssh/id_ed25519_github`，`~/.ssh/config` 里配置了走 `ssh.github.com:443`
（大陆直连 `github.com:22` 常被阻断，443 端口可通）。这是长期凭证，不用每次重建。
