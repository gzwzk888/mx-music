## 1. 技术栈与分层

| 层 | 技术 | 说明 |

| UI | React Native 0.73.11 + TypeScript | 老架构（非 Fabric），无 expo |

## 2. 播放链路

### 2.1 http 流当本地歌播放

RNTP 只接受本地路径或远程 URL，而 NAS 资源是
`http://<host>:8200/MediaItems/<id>.flac?type=1,...`。

- `src/utils/music.ts` → `getLocalFilePath()`：对 `http(s)` 原样返回，交给 RNTP 当远程流
- `src/core/nas/dlna.ts` → `toMusicInfo()`：DLNA 条目转 `MusicInfoLocal`，
  `meta.songId` 与 `meta.filePath` 都存 URL

### 2.2 CUE 整轨分轨

整轨音频被拆成 N 轨时**共用同一个音频 URL**，靠区间定位：

- `src/core/nas/cue.ts` / `cueIndex.ts` / `cueRanges.ts`：解析 `.cue`，算每轨起止时间
- 索引项带 `cueStart` / `cueEnd`，`nasIndexToCard()` 写入 `meta`
- 起播按 `meta.cueStart` 定位；`src/core/init/player/playProgress.ts` 到 `cueEnd` 自动切下一首
- **注意**：读区间要用 `playMusicInfo.musicInfo.meta`（完整对象），
  `playerState.musicInfo` 只有基础字段

### 2.3 进度

- 底栏 `src/components/player/PlayerBar/components/PlayInfo.tsx`：显示时间，**没有进度条**
  （原实现是 `absoluteFill + zIndex:100` 的透明触摸层，铺满整个托盘，点歌名附近就会 seek）
- 播放页进度条是独立组件，未受影响：
  `src/screens/PlayDetail/Vertical/Player/components/PlayInfo.tsx`（`ProgressBar`）、
  `src/screens/PlayDetail/Horizontal/Player/PlayInfo.tsx`（`Progress`）

## 3. NAS 模块（`src/core/nas/`）

| 文件 | 职责 |
|---|---|
| `dlna.ts` | SOAP Browse、XML 解析、`NasDevice` / `NasItem`、`toMusicInfo()` |
| `nasIndex.ts` | 全库索引构建（Folder 视图遍历）、`nasSongPathText()` |
| `session.ts` | 会话与缓存、**NAS 可达性探测**、本机曲库缓存 |
| `playStats.ts` | 播放统计、`getRecentSongStats()`、专辑聚合 |
| `cue*.ts` | CUE 解析与区间 |
| `embeddedArt.ts` | 远程 Range 两段式取内嵌封面 |
| `lyricSearch.ts` / `lyricSource.ts` | 歌词多源搜索 |
| `nasPlaylists.ts` | NAS 播单同步 |
| `mediaProps.ts` | 文件大小/属性（本地记忆 + 远程 HEAD） |
| `smbSession.ts` | SMB 会话保活 |

### 3.1 DLNA 的四个坑

1. **`res` URL 不是路径**：`http://host:8200/MediaItems/A0$128$129$1021051140.dsf`
   里的 `A0$128$129$...` 是服务器内部对象 ID。展示必须用索引里的
   `folder + title + ext`（`nasSongPathText`）
2. **`StartingIndex` 不可靠**：部分服务器忽略分页参数，翻页必须走文件夹树
   （`nasIndex.ts` 用队列逐目录 Browse）
3. **只在 Folder 视图遍历**：Songs / Artist / Album / Genre 等视图与文件夹树重复，
   遍历会成倍放大请求量（`VIEW_CONTAINERS` 白名单跳过）
4. **DLNA 只读**：写回歌词/元数据必须走 SMB

### 3.2 可达性探测（离线模式）

```ts
// src/core/nas/session.ts
isNasReachable(force = false, timeoutMs = 1500): Promise<boolean>
markNasUnreachable(): void
```

- 探测 `GET http://<nas.host>/`，1.5 秒超时（`AbortController` + `Promise.race` 双保险）
- 结果缓存 30 秒；NAS 曲目播放失败时立即标记不可达
- 调用方：`SongList/buildPool()` —— 离线时池子只装本机

### 3.3 播放统计

```ts
recordPlay(musicInfo)   // 由 global.state_event.on('playMusicInfoChanged') 触发
```

- 字段：`id / name / singer / album / picUrl / filePath / count / lastAt`
- `picUrl: meta.picUrl ?? prev?.picUrl ?? null` —— 不会被空值覆盖
- `getRecentSongStats(limit = 100)`：按 `lastAt` 倒序，键为「歌名+歌手」去重
- **没有上限**：`@mod_play_stats` 会随播放持续增长（万首级约 3–4 MB），是待优化项

## 4. 本机音乐

### 4.1 原生扫描（`android/app/src/main/java/.../media/MediaScanModule.java`）

- 查询列：`DATA / TITLE / ARTIST / ALBUM / DURATION / SIZE / MIME_TYPE / DISPLAY_NAME / ALBUM_ID`
- `path` = `MediaStore.Audio.Media.DATA`
- `picUrl` = `content://media/external/audio/albumart/<ALBUM_ID>`，`ALBUM_ID <= 0` 时为 `null`
- **权限模型**：`targetSdk 29` 在 Android 13+ 仍走旧模型，需请求 `READ_EXTERNAL_STORAGE`；
  只请求 `READ_MEDIA_AUDIO` 会被静默拒绝（`requestMediaPermission()` 两种都试）

### 4.2 前端（`src/screens/Home/Views/Local/index.tsx`）

- 结果持久化 `@mod_local_files`
- 播放时 `meta.picUrl = file.picUrl`、`meta.filePath = file.path`
- 旧缓存（无 `picUrl` 字段）会被自动检测并补扫：`isLocalCoverStale()` / `refreshLocalFiles()`

### 4.3 SSDP 自动发现

同一个原生模块的 `discoverDlna()`：原生 UDP M-SEARCH 组播（RN 层做不到）。
⚠️ 缺 `MulticastLock`，息屏后容易发现失败。

## 5. 歌单页（`src/screens/Home/Views/SongList/index.tsx`）

两个 tab（`recent` / `random`），大图网格，列数按容器实测宽度算（手机 3 列，平板 4–8 列）。

```ts
interface SongCard {
  key: string           // 去重键 = 歌名+歌手
  name, singer, album
  picUrl: string | null // 只放歌曲自身封面，空则落 logo
  from: '本机' | 'NAS'   // 卡片第三行
  info: LX.Music.MusicInfoLocal
}
```

### 5.1 「最近」

- `getRecentSongStats(100)`（最多 100，不足就有多少显示多少）
- 封面补全顺序：**NAS 索引命中**（拿 `artUrl` / CUE 区间 / 目录）→
  **本机曲库命中**（按 `filePath` 反查 MediaStore 封面，最新扫描优先）→ 记录自身字段
- 来源判定：`filePath` 以 `http(s)` 开头即 NAS
- 离线时 NAS 记录仍显示，播放失败会提示「NAS 可能已断开」

### 5.2 「随机100」

- 池子 = 本机曲库 + NAS 全库索引（按 `歌名+歌手` 去重）
- **NAS 不可达时只装本机**
- **点 tab 即刷新**：已在随机栏 → 重抽；否则切过去同时重抽
- 换批：记住上一批 key，优先抽没出现过的；池子不足 100 才允许重叠
- 池子缓存 30 秒（`poolRef`），`pickingRef` 防连点重入

## 6. 搜索页（`src/screens/Home/Views/LocalSearch/index.tsx`）

- 索引：`getLocalFiles()` + NAS 索引合成，**首次输入才构建**（避免启动遍历上万首）
- 匹配：歌名 / 歌手 / 专辑 / 路径，最多 500 条
- 历史：`@mod_search_history`，上限 20 条，1.2 秒防抖写入
- 每行三行文字：歌名 / 艺人·专辑 / 路径
  - 本机：去掉 `/storage/emulated/0`、`/sdcard`、`file://`、query；`content://` 直接不显示
  - NAS：`nasSongPathText(folder, title, ext)`
- 点击播放：全部结果装入「试听列表」再播当前

## 7. 歌词

### 7.1 同步微调（`src/core/lyricOffset.ts`）

```ts
const MIN_MS = -60000, MAX_MS = 60000      // ±60 秒
shiftLyricOffset(id, deltaMs)              // 100ms 对齐，最多记 800 首
formatLyricOffset(ms)                      // ≤59.9s → +12.5s；60s → +1m
```

- 存储 `@mod_lyric_offset`，只影响显示，不改歌词文件
- 应用点：`src/core/lyric.ts` → `Math.max(0, time + getLyricOffset(musicId))`（正数=提前）
- UI：`src/screens/PlayDetail/LyricOffsetModal.tsx`，一行 6 档
  `-3s -1s -0.5s +0.5s +1s +3s`

### 7.2 桌面歌词

- 原生 `android/.../lyric/`：系统悬浮窗（`SYSTEM_ALERT_WINDOW`）
- JS 侧 `src/core/desktopLyric.ts`、`src/utils/nativeModules/lyricDesktop.ts`
- 丢窗自愈：`ensureDesktopLyric` 在播放/设置变更时校验

## 10.1 安全基线

### 明文 HTTP

`android/app/src/main/res/xml/network_security_config.xml` 默认禁止明文，仅对只提供 http 的音乐平台开口：

```xml
<base-config cleartextTrafficPermitted="false" />
<domain-config cleartextTrafficPermitted="true">
    kuwo.cn / stsky.cn / kugou.com / music.163.com
    migu.cn / taihe.com / qianqian.com / ting.baidu.com
</domain-config>
```

依据：源码 355 处 URL 统计，纯 http 域名 38 个。少写一个域，对应音源就挂。改动后必须回归
五源（网易云 / QQ / 酷狗 / 酷我 / 咪咕）× 搜索 / 播放 / 歌词 / 封面。

### 组件导出

`MusicService` 来自 `react-native-track-player` 的 manifest（源码里没有，靠 merger 合并），
改 `exported` 要用 `tools:replace` 覆盖：

```xml
<service android:name="com.guichaguri.trackplayer.service.MusicService"
         android:exported="false"
         tools:replace="android:exported" />
```

保留 `<intent-filter MEDIA_BUTTON>`，系统媒体键仍可送达；被挡的是第三方 App 的 `bindService`。

## 11. 已知问题

1. `@mod_nas_index` 与 `@mod_play_stats` 体积随曲库/播放增长，进歌单要整体解析，久用会慢
2. 播放统计无上限
3. SSDP 缺 `MulticastLock`，息屏后自动发现易失败
4. DLNA 只给一层目录名，路径不是完整层级
5. 首次进歌单可能等最多 1.5 秒（NAS 探测）
6. 本机 `albumart` URI 在媒体库重建后可能失效（已改为曲库优先取值）
7. DSD 不支持
8. Release 关闭 proguard，包体偏大
9. `targetSdk 29` 走旧权限模型，Android 13+ 需按老规矩申请
